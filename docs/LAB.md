# Стенд

## Зачем

Тренироваться на реальных уязвимостях, не трогая ничей продакшен. Стенд повторяем:
поднял, сломал, сбросил, снова поднял.

## Схема

```
┌──────────────┐         ┌──────────────────────┐
│  твой хост   │──:3000──│ Juice Shop (v20.3.0) │
│              │──:8081──│ DVWA 1.9             │
└──────┬───────┘         └──────────────────────┘
       │
       │  pcap                Zeek 9.0.0
       └───────────────▶  logs/zeek/*.log
       │
       │  Wazuh single-node (vendor)
       └───────────────▶  :443 / :1514 / :55000
```

## Wazuh

```bash
make vendor   # git clone --depth 1 --branch v4.14.9
make siem
# UI: https://localhost — логин admin, пароль из vendor/.../config
```

Пароль по умолчанию меняется в `single-node/config/wazuh_indexer_ssl_certs` и
`docker-compose.yml`. Для стенда допустим дефолт, для чего-либо ещё — нет.

## Сценарии тренировки

| Сценарий | Роль | Что тренируем |
|---|---|---|
| SQLi и обход авторизации в DVWA | websec | базовые техники, ручной разбор |
| Поиск секретов в Juice Shop | websec | API, JWT, логика |
| Разбор pcap с эксфильтрацией | netsec | Zeek, таймлайн, IOC |
| Подозрительный вход в Wazuh | dfir | корреляция, алерты |
| Фишинговое письмо | soceng | заголовки, ссылки, pretext |

## Ограничения

- Стенд не является «боевой» инфраструктурой: данные не сохраняются.
- Запуск малвари — только `sandbox` с `network_mode: none` и снапшотом ВМ.
- Публикация портов только на loopback; проверяй `ss -ltnp` перед этапом.
